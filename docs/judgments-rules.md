# 写 judgments 的规矩（决定分数能不能跨机器一致）

## 为什么有这份文件

同一批材料，在这台电脑打 59.4 分，在另一台打 41.5 分。差 16.5 分。

**不是代码问题。** 我验证过：`score.py` 是纯函数，同一份 judgments 跑两次结果完全一致（哈希相同）。分数不同的唯一原因是 **judgments.json 不是同一个人写的**。

证据是两边同一份材料的判据：

| | 判据原文 |
|---|---|
| A 机器 | `按材料中实际可引用的证据定级：薄弱（证据点 3）` |
| B 机器 | `价值性只有一次定性实战案例（2026年9月盱眙难降解COD冲击当天预警、调控活性炭投加避免出水超标）加表2-1...` |

A 的判据是模板，看不出依据，**换个人重写必然给不同分数**。
B 的判据点了日期、地点、表号、具体数据，**换个人照着核也会给出接近的分数**。

这就是差异的根源。

---

## 规则一：rationale 必须点名原文

**不合格**（这些都能套在任何材料上，等于没写）：

```
✗ 按材料中实际可引用的证据定级：薄弱（证据点 3）
✗ 论证偏定性，缺具体数字与佐证
✗ 证据充分，符合要求
✗ 该维度表现一般
```

**合格**（换一份材料就写不出来）：

```
✓ 效益表只填了「预计节约 500 万元」，无改造前基准值，无法复算变化率；
  表3-2 的「实际值【已实现】」列全空，属于规划而非已实现。
✓ 推广只写了「已在多个厂推广」，无厂名、无数量；表4-1 列出 3 个案例但都无部署日期。
✓ 2026-05-26 上线至报送日 09-08 共 105 天，材料自述「已稳定运行 3 月」，
  与 90 天要求矛盾，需核对起算日。
```

**检查方法**：写完自问——把这段话贴到另一份材料上，还成立吗？成立就说明写得太空，重写。

---

## 规则二：quotes 必须逐字且能支撑结论

引文不是「找一句相关的话」，是「这句话能证明我给的分」。

**不合格**：

```
✗ 引用一句泛泛的背景描述，却用它支撑「价值性 A 级」
✗ 引文是自己概括的（「材料提到有推广」），不是原文
```

**合格**：

```
给价值性 B 级，引文必须是那个「有数字但缺基准」的原句：
✓ 改造后吨水电耗由 0.1069 降至 0.0784 kWh，年节约电费 202.745 万元

给推广性 C 级，引文必须是那个「只说了范围没说数量」的原句：
✓ 已在集团多个水厂推广应用
```

**机器会校验**：`score.py` 拿每条 quote 去原文逐字比对，找不到就拒收并降一级。拒收率高的 judgments 等价于没做功课。

---

## 规则三：先定级，再给分

等级决定封顶，顺序不能反。

| 等级 | 含义 | 判据要求 |
|---|---|---|
| A | 可复算 | 有数字 + 有基准 + 有佐证材料 |
| B | 部分佐证 | 有数字但缺基准或佐证 |
| C | 自述 | 只有定性描述 |
| D | 无佐证 | 只有目标/规划 |

**常见错误**：心里先想「这份材料还行，给 18 分」，再倒推等级 B。
正确做法：先看证据够不够 B 级，定了级，分数自然落在该级的区间里。

等级定错，分数必错，而且换个人一定给不同答案。

---

## 规则四：绑定材料（防止答案被抄）

judgments 装的是答案。放在材料旁边，任何进目录的人或 AI 一条 `ls` 就看见了。

写完必须绑定：

```bash
python scripts/bind_judgments.py <目录>
```

它会写入：

```json
"material_sha256": "5de29ee4...",
"material_name": "...",
"judged_at": "2026-11-03T17:12:00+08:00"
```

之后 `score.py` 会校验：**指纹对不上直接拒收，退出码 2。**

```
judgments 绑定的材料与当前材料不符，拒绝评分。
  judgments 里写的：5de29ee4e6f5e4ea
  当前材料实际是：a43a03e509773844
```

这样抄来的 judgments 用不上——就算分数一样，绑不上当前材料就进不了评分。

---

## 规则五：跑完别留答案

```bash
python scripts/batch.py <目录> --out <输出> --all --bind --no-keep-judgments
```

- `--bind`：打分前自动绑定指纹
- `--no-keep-judgments`：跑完删掉输出目录里的 `*.judgments.json`

要严一点就加 `--require-bound`：没绑定的 judgments 直接拒收，不做兼容。

## 自检清单

写完一份 judgments，逐条过：

- [ ] 每个 rationale 都点了原文的具体内容（日期/表号/数字/原句）
- [ ] 把 rationale 贴到另一份材料上会立刻露馅
- [ ] 每条 quote 都是原文逐字抄的，不是概括
- [ ] quote 能支撑我给的等级，不是「相关」而已
- [ ] 先定的等级，再给的分数
- [ ] 跑过 `bind_judgments.py`，有 material_sha256
- [ ] 跑完用了 `--no-keep-judgments`

七条全过，换一台机器重写，分数差异应该在 5 分以内。
少过一条，差异可能到 15 分以上。
