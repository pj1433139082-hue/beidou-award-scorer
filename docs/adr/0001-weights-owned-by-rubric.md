# ADR-0001 · 权重由评分卡拥有，不由代码拥有

**状态**：已采纳（2026-11-03） · 相关：GLOSSARY（评审）

## 背景

评审办法规定合成方式为「现场评审 75% + 书面/AI 评审 25%」。这个数字同时出现在两个地方：

- `rubric.example.json` 的 `scoring_rules.weights`：`{"on_site": 0.75, "ai": 0.25}`
- `score.py:253` 的表达式：`round(0.75 * on + 0.25 * ai_score, 1)`

后果：**改评分卡的权重完全不生效**。而评分卡里那份副本会让人以为它生效了——这比没有更危险。

## 决定

权重属于**赛事规则**，由评分卡拥有。`score.py` 从 `scoring_rules.weights` 读取，缺失时报错退出。

## 理由

它不是本工具的技术选择，而是官方规则的一部分——换一届赛事就可能变。写死在代码里等于假定规则永不变。

「它已在评分卡里」这个事实本身就是决定性证据：用户会去改它。

## 后果

- 评分卡必须包含 `scoring_rules.weights.on_site` 与 `.ai`
- 读不到时 `score.py` 以退出码 2 结束，并指明缺哪个键
- 不设现场评审的奖项（如金火炬）只用 `ai` 一项，由调用方决定是否传 `--onsite`

## 这条 ADR 拦住了什么

以后不要再把「合成比例」「封顶系数」「等级边界」这类**规则性数字**写进代码——它们都属于评分卡。
