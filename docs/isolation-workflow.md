# 隔离评分流程

## 问题

多 agent 并行评同一批材料时，最容易出的错不是「评得不准」，而是**评得一样**——
因为后跑的 agent 读到了先跑的判断。一旦如此，比对就失去意义。

**我们的实测数据**：第一轮千问和我 18/19 份分数完全相同（94.7%）。
原因不是巧合，是我在提示词里写了「已有的 judgments 必须复用」，
还给了路径。它照做了。

光靠提示词说「别看」没用。**真正隔离必须是结构性的。**

累积起来几百份，任何 agent 顺手一扫就全看到了。

## 流程

### 开始一次隔离

```bash
python scripts/isolate.py prepare <工作目录> \
    --materials "<原始材料目录>" \
    --skill "<技能目录>" \
    --rubric "<rubric.json>" \
    --label 千问
```

它做四件事：

1. 建干净目录：`材料/ 机检/ 输出/ skill/`
2. 只拷原始 docx/pdf 到 `材料/`（不拷任何判断）
3. 拷技能代码 + rubric（自动排除 `*.judgments.json`、`*.score.json`）
4. **跑机检**（确定性，两个 agent 必然相同，不算泄露）
5. **把所有已有判断藏到 `.dsh-isolation-hold\`**，写 `SEALED.json` 留痕

### 跑分前自检

```bash
python scripts/isolate.py check <工作目录>
```

```json
{"clean": true, "stray": [], "stray_count": 0, "sealed": true}
```

`clean: false` 就说明目录里混进了判断文件，**先清掉再跑分**。

### 结束后恢复

```bash
python scripts/isolate.py end <工作目录>
```

把 `SEALED.json` 里记录的目录全部移回原处，并把清单改名成 `.json.done`。

### 审计独立性

```bash
python scripts/isolate.py audit <我的目录> <对方目录>
```

输出：

```json
{
 "materials": 19,
 "identical": 18,
 "identical_ratio": 0.947,
 "verdict": "部分一致（95%）：可能共享了部分输入"
}
```

**判定规则**：

| 完全一致率 | 判定 |
|---|---|
| ≥ 95% | 可疑：几乎不可能是独立判断 |
| 70%–95% | 部分一致：可能共享了部分输入 |
| < 70% | 独立 |

这份数据就是上一次被污染的产物，audit 一跑就抓出来了。

## 提示词的写法

### 不能写

```
已有的 judgments（评审判断，必须复用，不要重写）：
D:\...\评分结果\*.judgments.json
如果该目录没有，从 %TEMP%\score-all\ 复制。
```

这段直接告诉对方「去拿我的判断」，比对必然失效。

### 应该写

```
只能读这个目录：<隔离工作目录>
绝对不要去找：任何 *.judgments.json、任何 *.score.json
如果你看到过，请在报告开头声明
```

### 两条要一起用

提示词约束是**软的**（依赖自觉），目录隔离是**硬的**（物理找不到）。
**两者必须同时用**：

- 只有提示词 → 对方顺着路径就找到了（我们已经遇到过）
- 只有目录隔离 → 对方可能去别处找
- 两者同时 → 找不到 + 被要求声明

---

## 下次怎么做

1. `isolate.py prepare` 建两个独立目录（每个 agent 一个）
2. 各自把自己的提示词发过去，**提示词里只写自己那个目录的路径**
3. 各跑 `check` 确认干净
4. 各自跑分、出报告
5. 全部结束后 `isolate.py audit` 比对
6. `isolate.py end` 恢复被藏的文件

**关键：两个目录要同时建，不要在 A 做完之后再建 B**——
否则 A 的产物有可能在 B 建目录之前又被扫进去。
