# judgments 模板（评审员填写，score.py 消费）

> 复制本文件为 `<报告名>.judgments.json` 后填写。**quotes 必须是原文逐字片段**（>=6 字），
> score.py 会在 doc.json 的 plain 里逐条比对；查不到的引文会被拒收并降证据等级。

```json
{
  "award": "金点子 | 金刚钻 | 金引擎 | 金智囊 | 金火炬",
  "judgments": {
    "<维度id>": {
      "score": 0,
      "grade": "A | B | C | D",
      "rationale": "一句话判据：为什么给这个分（对齐官方说明 + 材料里的具体事实）",
      "quotes": ["原文逐字片段1", "原文逐字片段2"]
    }
  },
  "disputes": ["你认为材质里含糊、需要答辩追问的点"]
}
```

## 证据等级（grade）定义

| 等级 | 名称 | 定义 | 分档区间 |
|---|---|---|---|
| A | 可复算 | 系统截图 + 运营日志/成本台账 + 独立验证，数字可被第三方按同一口径重算 | cap 1.00（区间 [0.75,1.00]） |
| B | 部分佐证 | 有佐证但口径未闭合，或缺部分时段/项目 | cap 0.75（区间 [0.50,0.75)） |
| C | 自述 | 仅有文字描述、PPT 结论、自评表格 | cap 0.50（区间 [0.20,0.50)） |
| D | 无佐证 | 只有目标/规划表述，或数据找不到出处 | cap 0.20（区间 [0.00,0.20)） |

> 四个档位互不重叠（左闭右开），`score.py` 启动时会校验，重叠直接报错退出。

## 打分纪律（务必遵守）

1. **AI 不是加分项**。技术属性（AI/数字化/传统技改）只做分类；把"用了 AI"当理由加分 = 违反官方 P12 的"评分导向校准"。
2. **先认证据，再给分**。score 不得超过该维度满分 × 该证据等级上限。
3. **已实现 vs 在研**。效益若未区分「实际值【已实现】/远期目标【规划/在研】」，按在研计（G2）。
4. **人工评审与 AI 差异 >10% 要写争议点**，不自行调分掩盖分歧。
5. **quotes 宁少勿编**。给不出原文逐字的判断，把 grade 降到 C 并说明缺什么材料。
6. **读不到就打 -1，不要打 0**。某维度确实无法判断（材料不可读、抽取失败），写 `{"score": -1, "unscored_reason": "..."}`。
   该维度会被排除出分母，而不是当 0 分拉低总分；报告里单列"未评分维度"。
